# Module CLI binary — `cmd/cgo` + `cmd/meteolink` as a standalone tool

Date: 2026-11-07. Scope: `cmd/cgo/*.go`, `cmd/meteolink/main.go`, `docs/api.md`, `docs/deploy.md` only. No code, no commit. Sibling `docs/research/2026-11-07-module-cli-frontend.md` covers `cmd/cgo-chr`, `cmd/cgo-gui`, `web/frontend`; this file does not duplicate it.

## Primary sources (R)

- R1 Go `go.mod` file reference — https://go.dev/doc/modules/gomod-ref (fetched 2026-11-07):
  module path is the module's unique identifier + import prefix, v2+ must end `/v2`; `go` is a mandatory minimum since 1.21; `require` is `path version` (SemVer `vX.Y.Z` or pseudo-version); single `go.mod` versioning; retraction needs a newer tag.
- R2 Semantic Versioning 2.0.0 — https://semver.org/ (fetched 2026-11-07):
  `X.Y.Z`; MAJOR = incompatible API, MINOR = backward-compatible feature, PATCH = backward-compatible bug fix; `1.0.0` defines the public API; released contents MUST NOT change; a public API MUST be declared.
- R3 Cobra — https://github.com/spf13/cobra (fetched 2026-11-07):
  library for modern CLIs similar to git/go tools; easy subcommands `app server`, fully POSIX-compliant flags (short & long), nested subcommands, global/local/cascading flags, intelligent suggestions, automatic help generation, automatic shell completion (bash/zsh/fish/powershell), automatic man pages, command aliases; flag functionality provided by the pflag fork.
- R4 urfave/cli — https://github.com/urfave/cli (fetched 2026-11-07; fallback reference only, since R3 was fetchable):
  declarative, simple, fast package; commands/subcommands with alias/prefix match, flexible help, dynamic shell completion (bash/zsh/fish/powershell), no dependencies except Go stdlib, documentation generation in man and Markdown (via `urfave/cli-docs` module); Go Reference badge shows module path `github.com/urfave/cli/v3`; `urfave_cli_no_template` build tag disables template-based help.
- R5 cobra.dev — https://cobra.dev/ (fetched 2026-11-07):
  automatic help generation, shell completion (Bash, Zsh, Fish, PowerShell) out of the box, man page generation, Markdown documentation (`doc.GenMarkdownTree`), POSIX-compliant flag parsing, command aliases, intelligent suggestions, generated by the cobra-cli scaffolder.

## 4. Primary-source requirements (what a standalone tool must satisfy)

### 4.1 CLI framework — R3 (Cobra, primary) vs R4 (urfave/cli, fallback) vs stdlib `flag` (today)

- Today: stdlib `flag.NewFlagSet(..., flag.ExitOnError)` per subcommand (`cmd/cgo/main.go:56,77,140,149,280`, `cmd/cgo/kit.go:16`, `cmd/cgo/calibrate.go:23`) + manual `switch os.Args[1]` (`cmd/cgo/main.go:43-302`) + hand-written `usage()` (`cmd/cgo/main.go:359-373`, `cmd/cgo/kit.go:22-61`). Observed consequences: no autogenerated help, no suggestions, no shell completion, no man pages, duplicated usage strings, long-only flags, and one mini-flagset (`cmd/cgo/setup.go:324-336`) that accepts `--yes`/`-yes` in any position — a third flag style beside `flag.FlagSet` and the hand-scanned `kit schedule` pairs (`cmd/cgo/kit.go:193-208`).
- Per R3, adopting Cobra requires: one `cobra.Command` tree, flags via pflag (POSIX short+long), global/local/cascading flags, auto help/completion/man, `did you mean` suggestions, aliases. Cost per R1: new `require` entries for Cobra + pflag in `go.mod`; Cobra is v1 so no `/vN` module-path suffix is needed (R1: only v2+ requires the suffix). R3's `APPNAME VERB NOUN --ADJECTIVE` pattern matches the existing `cgo kit <action>`, `cgo audit --link-type …`, `cgo run --profiles …` surface, so a Cobra tree is a structural fit, not a rename.
- Per R4, urfave/cli would require declarative `Command` structs, dynamic completion, man/Markdown docs via the `urfave/cli-docs` module, zero non-stdlib deps. Cost per R1: zero build-list growth, but the module path is `github.com/urfave/cli/v3` — the `/v3` suffix is mandatory for v2+ under R1, so `go.mod`/`go.sum` pinning must use the `/v3` path. R4's env/file input lookup maps naturally onto the existing `CGO_*` env reads (`cmd/cgo/main.go:57,292`, `cmd/cgo/server.go:35,43`, `cmd/cgo/runcli.go:79`), but that mapping is a design choice, not an R4 requirement.
- Decision rule (no new primary source needed): if the standalone must keep `bubbletea`/`lipgloss` out of the audit/serve binary (§3.2), either framework satisfies it; if it must add **zero** new `require` entries, only R4 satisfies it. Staying on stdlib `flag` violates no R1 rule, but any claim of POSIX flags, completion, or generated docs requires R3 or R4.

### 4.2 Go modules (R1)

- A standalone `cgo` repo needs its own `go.mod` with `module <unique-controlled-path>`, `go <minimum>`, `require <path> <vX.Y.Z>`. Per R1, the path must uniquely identify the module and ideally be the repo location; reusing `github.com/Realms4239/cgo` for the split without a `/v2` suffix or a new path would collide under R1's unique-ID rule.
- Every non-stdlib import needs a matching `require`: keeping `tui`/`kit tui` in the standalone keeps `bubbletea v1.3.10` + `lipgloss v1.1.0` (`go.mod:7-8`); dropping them lets `go mod tidy` remove them — only writable after the `package main` split (§7 S2).
- Tags are immutable once pushed; retraction needs a newer tag (R1 `retract`). Today releases use GoReleaser `name_template: cgo-{{ .Os }}-{{ .Arch }}` + `checksums.txt` SHA-256 (`.goreleaser.yaml`, `archives`/`checksum` blocks); any new layout must keep tag = version semantics per R1/R2.

### 4.3 SemVer (R2)

- Canonical version `KitVersion = "1.3.5"` — `internal/kit/kit.go:49-52` (single source; `cmd/cgo version` defaults to it — `cmd/cgo/main.go:41`), `VERSION:1` = `1.3.5`; a `-X main.version` release must equal the tag or CLI (`kit next`) and GUI diverge — `cmd/cgo/main.go:36-40`. Per R2, `1.3.5` parses as MAJOR 1, MINOR 3, PATCH 5, and `1.0.0` defines the public API.
- §1.3/§6 gap: the public API (CLI flags + exit codes §2.1, `pkg/api` HTTP/SSE) is not formally declared anywhere in `cmd/cgo/main.go`, `docs/api.md`, or `docs/deploy.md`. ## 8. Anti-toy criteria (a reviewer checks these, not prose)

Each criterion fails the slice if violated; citations are the standard being met.

1. **Generated, not handwritten, help.** `cgo <verb> --help` for every verb in §2.1 is generated by the framework tree (R3 automatic help generation / R4 flexible help). Fails if any verb's help is a hand-maintained string like `cmd/cgo/main.go:359-373` or `cmd/cgo/kit.go:22-61`.
2. **Every flag is discoverable.** Each flag in §2.1 (`--addr/--tls/--http-addr/--mode`, `--profiles/--qdiscs/--cc/…`, `--link-type/…`, kit's five) appears in its verb's `--help` with default and usage. Fails if a flag exists only in code (today: `--matrix` in prose only — G3) or a verb exists only in code (`schedule` — G3).
3. **Suggestions + aliases.** A typo'd verb suggests the nearest real verb (R3 intelligent suggestions / R4 alias+prefix match). Fails if `cgo auditt` prints generic usage with exit 2 and no suggestion.
4. **Exit-code contract preserved.** S1's table is probed by script: `audit` partial → 2 (`cmd/cgo/main.go:266-278`), `run` double-launch → 3 (`cmd/cgo/runcli.go:58-61`), `run` dead bench → 4 (`cmd/cgo/runcli.go:211-215`), `kit` 2–8 (`cmd/cgo/kit.go:58-59`), usage → 2. Fails if the framework's default error exit (typically 1) leaks through any verb.
5. **Completion is real.** Generated bash/zsh/fish/powershell completions cover verbs **and** flags, are byte-stable, and complete a kit action name. Fails if completion lists only top-level verbs. (Exact CLI for generating them: `unverified — primary source not found`, §4.4 — the criterion is the generated artifact, not the command.)
6. **No dead surface.** Every documented verb/flag exists in code and vice versa: `grep` over `docs/` + `usage` output vs the command tree must be a bijection. Fails on G2/G3/G4 residues (`--serve` without alias note, `meteolink top --addr`, `setup)→dashboard` no-op, `--matrix`).
7. **Version is single-sourced and true.** `cgo version` output == `VERSION` == `-X` tag == `KitVersion` (`cmd/cgo/main.go:36-41,74-75`, `internal/kit/kit.go:52`); no `1.2.3` remains in `docs/`. Fails per R2 if any of the four disagrees.
8. **Module hygiene (R1).** `go list -m all` for the standalone shows only modules actually imported by the shipped binary; `meteolink` is not a second module (G6); no `fyne.io/fyne` (G7) unless the TUI is deliberately kept in the same binary and justified in the slice note.
9. **Standalone means standalone.** From a clean checkout + Go toolchain only (no repo sibling, no `kit/*.sh`, no frontend `bun` build), `go build ./cmd/cgo` succeeds and `cgo doctor`, `cgo version`, `cgo kit --help`, `cgo audit --help`, `cgo run --help` run. Fails if any of these needs the monorepo layout (`mustRepoRoot` — `cmd/cgo/setup.go:297-312` — must be scoped to `setup` only, not the whole binary).
10. **Docs are generated or golden.** Man pages / Markdown for the command tree are generated (R3/R5) or committed as golden files diffed in CI. Fails if `docs/` help text is hand-typed and can drift like `cmd/cgo/main.go:363` did.
