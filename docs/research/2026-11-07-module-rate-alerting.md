## 1. Responsibility

`pkg/campagne` is the measurement-cell orchestrator, not an alerting or rate-limiting component: `RunEvent` executes one matrix cell end-to-end (baseline → charge → recovery, `pkg/campagne/campagne.go:302`) and freezes a line, `StartMatrix*` runs the profile × qdisc × CC × rep matrix (`pkg/campagne/matrix.go:65,74,79,87`), and `StartWatch` runs a non-intrusive ping+small probe loop outside campaigns (`pkg/campagne/watch.go:23`). Its only alert-like behaviour is the in-process deadline sentinel in `StartWatch`: 10 consecutive over-deadline small-p95 evaluations journal one alert, throttled to 1 per 5 min (`pkg/campagne/watch.go:62-70`), via the package hook `OnWatchAlert` (`pkg/campagne/watch.go:15`) which the host wires to `api.RecordEvent("alerte", …)` (`cmd/cgo/server.go:101-103`) — a journal entry, with the code comment stating "pas de notification externe" (`pkg/campagne/watch.go:22`). The "rate" in this package is link shaping (`tc` netem/shaper caps, `pkg/campagne/campagne.go:358-371`), not request rate limiting.

`pkg/api/metrics.go` is a hand-rolled Prometheus text exporter: `renderMetrics` builds the exposition body (`pkg/api/metrics.go:17-41`) and `handleMetrics` serves it at `GET /metrics` (`pkg/api/server.go:397-399`). It exports no rate limiting of any kind: a repo-wide search finds no `golang.org/x/time/rate`, `RateLimiter`, `429`, or `TooManyRequests` in Go code, and `go.mod:5-10` requires neither `golang.org/x/time` nor any Prometheus client module (R5: a module's dependencies are declared by its `go.mod` `require` directives). The only request rate limiting in tree is Nginx `limit_req` (`deploy/nginx/cgo.conf:1-2,25`, reject status `deploy/nginx/cgo.conf:9`) — an ingress concern, cross-referenced here only because this brief names "pkg/api rate limiting": that surface is empty in Go.

`deploy/prometheus/rules.yml` (26 lines, `deploy/prometheus/rules.yml:1-26`) is the only alerting artifact: one recording rule (`cgo:slo:deadline_ok_pct_5m`, `:4-5`) and three alerts (`CGO_deadline_breach_sustained` `:6-12`, `CGO_probe_dead` `:13-19`, `CGO_iface_invalid` `:20-26`). It is not referenced by any file under `deploy/` (no `rule_files`, scrape config, or Prometheus/Alertmanager service in `deploy/docker-compose.yml:1-13`, which defines only the `cgo` service), so as shipped it is unloaded by any in-tree Prometheus.

### 4.5 Go modules — what extracting the tool entails (R5)

R5: "A module is a collection of packages that are released, versioned, and distributed together"; the module path is declared by the `module` directive in `go.mod` and is the prefix of package import paths; `require` declares "a minimum required version of a given module dependency" resolved by minimal version selection; adding a dependency means the `go` command records it via `require` (R5 "Modules, packages, and versions", "Resolving a package to a module", "require directive"). Consequences for `cgo-alerting`: it gets its own `module` directive (a `github.com/Realms4239/cgo-alerting`-style path, R5 module-path conventions) and its own `go.mod`/`go.sum`; importing `pkg/campagne` or `pkg/api` from it would require those packages to be in a released module version — today they are packages of the main module `github.com/Realms4239/cgo` (`go.mod:1`), i.e. internal. Whether `replace` directives or a monorepo `go.work` are the intended extraction path is a repo decision, not a primary-source one; `replace` semantics are R5 "replace directive" (main-module only, needs a matching `require`).

### 4.6 Rate limiting *in Go* — reference, not current behaviour (R6)

R6: `NewLimiter(r Limit, b int)` "allows events up to rate r and permits bursts of at most b tokens"; `Allow` reports whether an event may happen now; `Reserve` returns a future reservation; `Wait` blocks until a token is available; "Limiter is safe for simultaneous use by multiple goroutines" (R6 `Limiter`). `Sometimes{Interval: …}` runs a function at most once per interval (R6 `Sometimes`, example: "logging with rate limiting"). This is the correct tool if a Go-side mutation limiter is ever added — the watch sentinel's manual 5-min throttle (`pkg/campagne/watch.go:65`) is a hand-rolled `Sometimes{Interval: 5m}`. Adding `golang.org/x/time` is a new-dependency decision under R5 (`require` + `go.sum`), and the repo's AGENTS.md stop-and-ask rule ("a new dependency") applies — recorded, not assumed.

## 5. Gap analysis (ranked)

1. **Rules reference series the exporter never emits — two alerts can never fire, one record is empty.** `cgo_cap_deadline_ok_pct` (`deploy/prometheus/rules.yml:5`) and `cgo_cap_sla_breach` (`:7`) appear nowhere in `pkg/api/metrics.go:46-53` (the only emitted series are the six in `:47-52`). Under R2 an alert fires only when its expr "results in one or more vector elements" — an expr over absent series never fires. `CGO_deadline_breach_sustained` is therefore dead, and the recording rule records nothing. Which CAP computation would feed them (`pkg/metrics` thresholds/assessment) is outside the investigated files — emission binding is **`unverified — primary source not found`** in this pass.
2. **The exporter emits fabricated zeros, so the two remaining alerts fire permanently (or never, depending on scrape).** `handleMetrics` returns static `0` samples (`pkg/api/metrics.go:46-53`) with no reader of audit/iface state, and drops `getBuildInfo` (`:43,63` vs `pkg/api/server.go:397-399`). `CGO_iface_invalid` (`cgo_iface_valid == 0`, `deploy/prometheus/rules.yml:21`) is thus always true once scraped, and `CGO_probe_dead` (`rate(cgo_audit_load_measured_total[5m]) == 0`, `:14`) is always true for a constant-zero counter. The builder's own contract — "Absent is never emitted; the caller only pushes measured values" (`pkg/api/metrics.go:15-16`), tested at `pkg/api/metrics_test.go:30-43` — is violated at the endpoint, which pushes unmeasured zeros. R1's "little-to-nonexistent metric contract validation" (§4.1) means Prometheus will accept these zeros without complaint.
3. **Watch sentinel duplicates Prometheus alerting in-process and pages nobody.** `StartWatch`'s 10×/5-min sentinel (`pkg/campagne/watch.go:62-70`) re-implements `for:` + notification throttling that R2 assigns to Prometheus (`for` clause) and Alertmanager ("notification rate limiting, silencing", R2). Its output is a journal line (`cmd/cgo/server.go:101-103`), explicitly "pas de notification externe" (`pkg/campagne/watch.go:22`). Two alerting paths (sentinel vs rules.yml) share the same deadline concept with different thresholds (10 consecutive ticks at 500 ms, `pkg/campagne/watch.go:37,65`, vs `for: 5m`, `deploy/prometheus/rules.yml:8`) and no doc reconciles them.
4. **No Go API rate limiting exists; the only limiter is invisible.** As §1 establishes, Go code has no limiter. Nginx rejects over-burst mutations with `503` (`deploy/nginx/cgo.conf:9`) and exports no per-zone counter in OSS (sibling ingress research, not re-derived here). For *this* tool the consequence is narrow: rate-limit rejections cannot be alerted on from `rules.yml` because no `cgo_*` series counts them — an observability gap, not a limiter gap.
5. **Hand-rolled exposition has a live escaping bug and a typing heuristic.** Label values are interpolated unescaped (`pkg/api/metrics.go:34`) against R1's escaping requirement (§4.1); TYPE is inferred from the `_total` suffix (`:27-29`) against R1's "missing TYPE ⇒ `untyped`" rule. Both are latent until a label value contains `"`/LF or a metric is misnamed — i.e. exactly when a new collector is added.
6. **Rules are untested and unloaded.** No `promtool test rules` file (R4, §4.4), no `promtool check rules` evidence (R3), no `rule_files` loading config (§1), no Alertmanager (R2 notification layer, §4.2). `keep_firing_for` is unset on all alerts (R2 default: deactivate on first non-match), summaries are untemplated (§4.2), and the recording rule's group inherits cadence from a nonexistent global config (R3).
7. **`rate()` on a percentage gauge is asserted without a primary source.** `avg(rate(cgo_cap_deadline_ok_pct[5m]))` (`deploy/prometheus/rules.yml:5`) — correctness of `rate()` for a 0–100 percentage is **`unverified — primary source not found`** (PromQL reference not fetched); regardless, its input series does not exist (gap 1), so the record is empty today.
8. **Config freeze vs live metrics drift.** `DeadlineMs` is frozen into the run manifest (`pkg/campagne/config.go:27,114-120`) and used by `RunEvent` (`pkg/campagne/campagne.go:43-45`), while `StartWatch` reads it from `defaultDeadline()` at start (`cmd/cgo/server.go:146-148`) and the Prometheus alerts hard-code durations (`deploy/prometheus/rules.yml:8,15,22`). Three sources of "the objective", no single registry — the metrics contract and the thresholds can drift silently.

## 6. Target tool: `cgo-alerting` as independent repo

Extract the observability surface (exporter + rules + watch sentinel contract) into its own repository (or OCI artifact family) so it can be versioned, tested with `promtool`, and rolled back independently of `cgo`. Proposed shape — every element traces to §4:

## 8. Anti-toy criteria (what would make `cgo-alerting` unacceptable as a standalone tool)

A submission fails review if any of these holds:

1. **Dead rules.** Any alert/record expr names a series the exporter does not emit (today: `deploy/prometheus/rules.yml:5,7` vs `pkg/api/metrics.go:46-53`) — silent-green dashboards. Every expr must resolve against a live scrape (R2 firing semantics).
2. **Fabricated zeros.** The endpoint emits counters/gauges with no reader of live or frozen state (today: `pkg/api/metrics.go:46-53` static `0`, `site="unknown"`). Absent must be absent, per the repo's own invariant (`pkg/api/metrics.go:15-16`) — R1 will not catch this for you (§4.1).
3. **Always-firing / never-firing by construction.** A `== 0` alert over a hard-coded zero (`deploy/prometheus/rules.yml:14,21`) or a `== 1` alert over a never-emitted flag (`:7`) with no test proving both states. Each alert needs an R4 `alert_rule_test` covering firing and non-firing.
4. **Unescaped or mis-typed exposition.** Label values interpolated verbatim (`pkg/api/metrics.go:34`) or TYPE guessed from `_total` (`:27-29`) against R1's escaping/TYPE rules. A `"` in a label value must not corrupt the scrape.
5. **Two paging paths.** The in-process sentinel (`pkg/campagne/watch.go:62-70`) and Prometheus rules both claim to alert on the same deadline with different thresholds and neither pages (journal only, `cmd/cgo/server.go:101-103`; R2 assigns notification to Alertmanager). One path pages; the other may log.
6. **Unloaded rules.** `rules.yml` with no `rule_files` config, no scrape target, no Alertmanager (today: nothing under `deploy/` references it, §1). A rules file no Prometheus loads is a document, not an alert.
7. **Asserted PromQL without a source.** `rate()` semantics, `absent_over_time` replacements, or record-rule rewrites claimed without the PromQL reference fetched (gap 7: **`unverified — primary source not found`** until then).
8. **Mutable identity / no rollback.** `:latest` image, unpinned exporter, or a release with no named prior digest + one-command rollback. The exporter digest must be immutable once published (R5 versioning: a version is "an immutable snapshot of a module", R5 "Versions").
