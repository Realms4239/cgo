## 1. Responsibility

**Air-gap distribution owns one job: produce a self-contained bundle that an offline host can unpack, verify, and run with zero network calls — and prove it did so from the bundle's own files.**

In scope:

- Assembling every runtime artifact for a pinned release (static `cgo` binaries, OCI image tarball, bench scripts, example config, operator guide) into one directory or tarball with a manifest.
- Emitting machine-readable integrity records (per-file checksums, SBOM in CycloneDX/SPDX, build provenance identifying the bundle by cryptographic digest) so the offline host can verify *before* executing anything (R4, R5).
- Providing an offline loader/ verifier (`verify` + `load`/`up` path) that fails closed on mismatch; no silent fallback to network fetch.
- Pinning identity (version tag ≠ mutable tag; digest-pinned OCI reference) and stating the achieved SLSA level per bundle (R4).

Out of scope:

- Product behaviour (audit, campaign, shaping, bench measurement) — the bundle distributes the binary, it does not implement it.
- Online registry operations (publish, push, pull from a networked registry) — distribution *to* the registry is online; distribution *from* the offline bundle is the air-gap surface. OCI distribution to a registry speaks the Distribution Spec API (R1); the same image can travel as a detached tarball (`docker save` / `docker load` semantics — **`unverified — primary source not found`** for the OCI-spec-level file format in this pass; the bundle consumes whatever the runtime exports, it does not invent a format).
- In-product telemetry or update checks — the bundle must run inert offline; any phone-home is a defect, not a feature.

The current repo partially performs this job by hand (`cgo kit package`, `npm/install.js`, README release flows) but produces no verifiable bundle: no manifest, no SBOM, no signing, no provenance. That is the gap this module closes (see §5).

## 3. Dependencies

**Build-time (needed to produce the bundle — all online at producer, none at consumer):**

- Go toolchain 1.25+ (`go.mod:3`; `internal/kit/package.go:40,328` gates on `exec.LookPath("go")` and fails closed without it; `Makefile:1` `GO ?= go`) and `bun` + the frontend build (`Makefile:38-39`) — the embedded SPA must be rebuilt *before* the binary or `embed.go` ships a stale `dist` (`README.md:304` already warns `go vet` needs `web/frontend/dist`).
- Syft (or equivalent SBOM generator) if the GoReleaser SBOM pipeline is used — GoReleaser's default `cmd: syft` for archives (R2). OCI images are *not* catalogable by that step (R2 “Limitations”), so the image SBOM needs a separate producer (`syft <image>` / cosign-attest — **`unverified — primary source not found`** for the exact flag surface in this pass).
- cosign / sigstore for signing (R6) — not yet a dependency; proposed (§6). Key-custody choice (keyless OIDC vs. self-managed keys) is **`unverified — primary source not found`** for this org (no policy read; R6 index only).
- An OCI runtime/registry client to export the image tarball for offline load — Docker/`docker save`/`docker load` semantics are **`unverified — primary source not found`** at the OCI-spec level in this pass (R1 covers the image format + Distribution API, not the save-file layout).

**Runtime (offline host — must be satisfiable from the bundle alone):**

- POSIX shell utilities already assumed by the installer scripts (`kit/vm-install.sh`, `kit/guest-setup.sh`) — `sha256sum`, `tar`, `docker load` where the image path is used; the verify step must degrade to `Verification failed` (non-zero exit, no execution) rather than “tool missing, run anyway” when a verifier is absent.
- Host kernel/tooling for the bench rôle (`tc`/`netem`, `tcp_bbr`, `iproute2`) per `docs/deploy.md:57-66`, `kit/install.sh` — these are *bench* deps, not *distribution* deps; `cgo-dist` ships the binary that needs them, it does not install them (offline or otherwise).

**Explicit non-dependencies of an air-gap bundle:** no registry, no DNS, no NTP, no CDN, no `GOPROXY`/`npm` fetches after sealing. `npm/install.js:123-147` (`httpsGet` with redirects) is the canonical anti-pattern: the bundle must *replace* that path with file-local verification, not wrap it.

## 5. Gap analysis — no OCI / SBOM / signing today

1. **No release automation, no `.goreleaser.yaml`.** `glob` proves absence (§2). Consequences, each directly contradicting a primary source:
   - No `sboms:` block → no SBOM is ever cataloged (R2). The `kit package` zips (`internal/kit/package.go:64,341`) contain binaries + scripts + README and nothing describing their components (R5 unmet).
   - No `checksum:` config → the `.sha256` sidecar in `README.md:85-86` is produced by hand (operator-wielded `sha256sum`), not by the build; it can drift, be forgotten, or cover the wrong file. R3's default (build-generated `checksums.txt`, sha256) is the correct shape and is absent.
   - No reproducible build definition → `internal/kit/package.go:38-44,123-129,333-339` rebuilds with host-dependent `go build` invocations and embeds whatever `web/frontend/dist` happens to hold; two runs can produce different bytes (frontend timestamps, build paths). R4 “follow a consistent build process” cannot be claimed, let alone proven.
2. **No OCI distribution discipline.** `deploy/docker-compose.yml:3` pins `:latest` (mutable). R4/SLSA + semver practice forbid moving a released version's contents; the SLSA-correct reference is `repo@sha256:<digest>` (R1 content-addressing). `docs/deploy.md:182-183` *claims* “digest-pinned image … rollback is compose pull of the prior digest” while the file ships a moving tag — the doc is literally false of the artifact. The Dockerfile itself (`deploy/Dockerfile:1-4`) has no `org.opencontainers.image.*` labels, no `USER`, no `HEALTHCHECK`, and no `GOOS/GOARCH` pin (architecture is whatever `bin/cgo` the build host produced — a Windows `.exe` copied in breaks silently; cf. `docs/VERIFY.md:27` cross-build note on `cmd/cgo-gui`).
3. **No signing, no provenance, no SBOM.** Grep across the tree returns zero `cosign`/`sigstore`/`syft`/`sbom`/`cyclonedx` *configuration*; the only hits are comments in `npm/install.js` and proposal docs. Against R4: at best the repo claims SLSA L0 (no provenance distributed); against R5: zero machine-readable inventory; against R6: no signature to verify. `docs/VERIFY.md:26` seals the *frozen corpus* with a hash list and explicitly narrows itself: “Proves a static anchor only: not a signature” — correct, and exactly the ceiling the *distribution* currently shares. A consumer of a release bundle today has nothing equivalent even at that level.
4. **The npm path assumes the network it claims to replace.** `npm/install.js:123-176` performs HTTPS GETs to `github.com/.../releases/download/...` with redirect following and exits 1 on 404 — correct online behaviour, fatal offline. No offline mirror, no `file:` fallback, no checksum check before `extractFromTarGz`/`extractFromZip` (`npm/install.js:178` extracts, then writes; there is no `sha256sum` gate). Air-gap hosts invoking `npm install` get a hard failure with no bundle to fall back to, because no bundle exists as an artifact.
5. **The only “verify” story is procedural.** `internal/kit/package.go:147` (`kit verify`: “empreintes SHA-256 des archives, recalculées sur la VM”) recomputes hashes on the VM, but with no expected-value anchor shipped in the archive, recomputation alone detects nothing — it is a measurement, not a verification. R4 “Provenance Exists” (digest-identified output + how it was produced) and R3 (build-generated checksums *with* the release) both require the anchor *beside* the artifact; neither exists.
6. **Identity sprawl.** Version lives in source (`internal/kit/kit.go` `KitVersion`, per `docs/research/2026-11-07-module-deploy-supplychain.md:102`, plus `cmd/cgo/main.go` default and `npm/package.json`), with no single generator from the git tag. Without a `.goreleaser.yaml` `-ldflags -X` binding, `cgo version` ≠ tag drift is already warned about in code. R4's “consistent build process” + the bundle manifest both require one version source; today there are several.
7. **What is *not* a gap.** The binary itself (`web/frontend/embed.go:11`) is genuinely air-gap-suitable: one static file, SPA embedded, `Dockerfile` scratch. The manual `sha256sum -c` ritual (`README.md:86`) is the right *shape* (detached checksum). The eBPF `.sha256` sidecar (`Makefile:56`) proves the hash-file habit exists. The module is therefore an *assembly + proof* gap, not a binary gap.

## 6. Target tool — `cgo-dist` as bundle builder

`cgo-dist` is a **bundle builder**, not a product. It lives in its own repo (checkout at the same time as `cgo`, never inside the measurement surface) and its entire API is: *given a pinned `cgo` release commit and a toolchain pin, emit one air-gap bundle directory + its proof files; given a bundle directory, verify and load it offline.* Sketch of the contract (implementer-facing, not yet built):

```
cgo-dist/
  cgo-dist.toml        # the consistent build description (R4 "Follow a consistent build process")
    [bundle]  name, version (generated from git tag), sbom_format="cyclonedx-json"
    [inputs]  cgo_commit = "abc123…", go="1.25", bun="<pin>", frontend_commit="…"
    [artifacts] binaries=[linux/amd64, windows/amd64], image="…@sha256:…"
  bin/cgo-dist         # single static binary (Go, stdlib-first; same embed trick as cgo)
  dist/<version>/
    cgo-<os>-<arch>.tar.gz|.zip     # from GoReleaser builds (R2/R3 pipeline)
    cgo-oci.tar                      # docker-save export of the digest-pinned image (R1)
    compose.yml                      # digest-pinned image: …@sha256:…  (never :latest)
    rules.yml + cgo.conf.ejs        # bench/edge config (cert paths templated, no fake TLS)
    SBOM.cyclonedx.json             # R5 machine-readable inventory, as a FILE
    provenance.json                 # R4 L1: {artifact digests, cgo_commit, builder, cgo-dist.toml hash}
    checksums.txt                   # R3 detached sha256 over every file above
    MANIFEST.json                   # bundle index: version, files[], modes, roles
    VERIFY.sh / verify.ps1          # offline loader: sha256sum -c, provenance check, docker load
```

Boundary rules:

- **Reads** the `cgo` release (binaries, image digest) and the toolchain pin; **never** patches `pkg/`, `cmd/`, `web/frontend/`, `book/`, `kit/` measurement code. It packages bytes; it does not change them.
- **Owns** `cgo-dist.toml`, the bundle layout, the SBOM/provenance/checksum emission, and the offline verifier. The verifier is the same code path in CI (a bundle that cannot verify in CI does not ship).
- **States its SLSA level per bundle** (R4): L1 from the first release (provenance exists, digest-identified); L2 once hosted CI signs provenance (R6 keyless or self-managed — decision recorded in `cgo-dist.toml`, not assumed); L3 explicitly out of scope until builds are isolated/ephemeral.
- **Refuses to use the network at verify/load time.** Any code path that opens a socket during `verify` is a bug, testable by running the loader under a disabled NIC in CI.
- **Replaces** the `npm/install.js` HTTPS path for offline hosts: the npm package keeps its online behaviour, but the *bundle* becomes the offline install path (`tar xzf … && ./VERIFY.sh && ./cgo kit …`). Both paths verify the same `checksums.txt`.

## 7. Slices (proposed, each independently acceptable)

- **S1 — Offline manifest + verifier (no signing infrastructure yet).** Extend `kit package` output (or seed `cgo-dist`) to emit `MANIFEST.json` + `checksums.txt` (R3 shape, sha256) over every file in the zip/tarball, plus `VERIFY.sh` doing `sha256sum -c checksums.txt` and failing closed (exit ≠ 0, no execution) on mismatch. Acceptance: a bundle directory produced on the build host verifies clean on a network-disabled VM/CI container; a one-byte mutation in any file is caught by the verifier (fault proof in the style of `tools/verify.py` `prove_*`); `sha256sum -c` succeeds from the bundle root with no network.
- **S2 — GoReleaser `sboms:` + `checksum:` for archives/binaries.** Add `.goreleaser.yaml` with `builds` (linux/amd64, windows/amd64, `-ldflags -X` binding `cgo version` to the tag), `archives` (`cgo-<os>-<arch>.tar.gz`/`.zip`), `checksum` (R3 defaults), `sboms:` (R2: `cmd: syft`, `artifacts: archive`, `args: ["$artifact","--output","cyclonedx-json=$document"]`). Acceptance: a pre-release emits archives + `checksums.txt` + per-archive CycloneDX JSON; the JSON parses, lists the `go.mod:5-10` direct deps (expanded), and `sha256sum -c` passes against the emitted checksums file. Note the R2 limitation: images are excluded — S3 covers them.
- **S3 — Digest-pinned OCI publish + offline image tarball.** Publish the scratch image by digest; switch `deploy/docker-compose.yml:3` from `:latest` to `ghcr.io/realms4239/cgo@sha256:…` (or at minimum `:<semver>`), add `org.opencontainers.image.*` labels at build time, and make S1's bundle carry the `docker save` tarball + the digest-pinned compose so `docker load && docker compose up` works with no registry (R1). Acceptance: `docker-compose.yml` and `docs/deploy.md:182-183` agree literally; compose pulls the digested image online and the tarball loads offline; the bundle manifest records both the tag and the digest.
- **S4 — Image SBOM + signing + SLSA provenance (L1 → L2).** Produce the OCI image SBOM off-image (`syft <image> --output cyclonedx-json`) and ship it as a bundle file (R2 limitation means it cannot come from the GoReleaser SBOM pipe). Sign the image + archives with cosign (R6) and publish `provenance.json` identifying each artifact by cryptographic digest with build inputs (R4 L1). Acceptance: `cosign verify <image>@<digest>` (or blob equivalent) green from the bundle's trust root; provenance digest matches `sha256sum` of the artifact; release notes state the achieved SLSA level (L1, or L2 if hosted signing is in place).
- **S5 — Air-gap hardening + CI fault proofs.** Network-disabled CI job: build bundle → `sha256sum -c` → `docker load` → `docker compose up` → `/api/health` green; negative jobs: mutated binary, mutated SBOM, missing file, wrong digest — each must fail with a named error and zero execution. npm offline path: document (and test) that `npm install` on a host fed *only* the bundle either installs from the bundle or fails with “offline: use the bundle” — never silently hits `github.com`. Acceptance: all four negative cases red in CI; the positive offline run green; `cgo version` == tag == bundle `MANIFEST.json` version.

Out of scope for this module: bench measurement code, the in-binary verifier (`tools/verify.py` ships alongside and gates releases but is not the release artifact), and the frontend bundle itself (separate module research).

## 8. Anti-toy criteria

A `cgo-dist` submission fails review if any of these holds:

1. **Mutable identity.** `:latest`, branch-name tags, hand-copied binaries with no `.goreleaser.yaml`/build description, or a `cgo version` that can drift from the tag. A released artifact's digest must be immutable once published (R1 content-addressing; R4 consistent build).
2. **Unverifiable payload.** No detached `checksums.txt` verifiable by `sha256sum -c` (R3), or no machine-readable SBOM *as a file in the bundle* (R5). “Trust the zip” fails; a URL to an SBOM fails harder offline.
3. **Provenance-free bundle.** No `provenance.json` identifying the bundle's artifacts by cryptographic digest with how they were produced (R4 “Provenance Exists” / L1 minimum). A hash list that nobody signed is L1 at best — say so; never imply L2/L3 without hosted, signed, isolated builds (R4).
4. **Networked verify/load.** The verifier opens a socket, follows a redirect, or consults a registry/DNS to decide validity (cf. `npm/install.js:123-147`). Air-gap means the decision is made from bundle files alone; tested under a disabled NIC.
5. **Image without identity.** The OCI image lacks `org.opencontainers.image.*` provenance labels, or compose still pins a mutable tag (R1). The image must be inspectable (`docker inspect`) and pinned by digest before the bundle claims it.
6. **Silent host mutation.** Install/load scripts that switch the host default congestion control, rewrite `/etc/hosts` outside an opt-in, shape traffic without a `--restore` escape, or execute anything before checksum+provenance pass. The existing `install.sh` correctly never touches default CC; `cgo shape --restore` (`docs/deploy.md:99-104`) must remain the escape hatch — keep both properties.
