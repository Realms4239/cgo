## 14. Error Handling (global)

- Unauthenticated mutation → `401` + `WWW-Authenticate: Bearer` (RFC 9110 §11.6.1/§15.5.2); CSRF → `403` (RFC 9110 §15.5.4); rate-limited → `429` + `Retry-After` + `Cache-Control: no-store` (RFC 6585 §4, RFC 9110 §10.2.3). Current Nginx `limit_req_status 503` (`cgo.conf:9`) MUST migrate to 429 (T19-S1 / T20-S2). Challenge on every 401; constant-time compare (`crypto/subtle`, never `==`); token loaded once (constructor, ≤1 `os.Getenv` in `guard.go`).
- Invalid `run_id` → `400` (`validRunID`, `server.go:320`); tier change mid-campaign → `409`. Audit without measured capacity → `422` (`server_audit.go:489`); no audit → `404` (`:439`); unknown CLI flag → usage exit 2; framework default error exit (typically 1) must never leak through any verb (T23 anti-toy 4).
- Scrape failure → target-down alert; `iface_valid:false` ⇒ gap reason (`warmup/absent/reset/slow/read/clock`). Missing series ⇒ `absent()`/`absent_over_time()`, never `== 0` on empty vector. `rate()` counters-only; `absent()` for missing series; `avg_over_time()` for percentage windows.
- Absent corpus → exit 2 naming absence; partial/corrupt → exit 1 naming file. Never exit 0 on partial tree (SKIP hole closure: `GateFailed` includes skipped files by name; brief repeats verifier logic). Green run on partial tree is a false claim.
- Live-scope refusal (`--scope live` without named condition; `--require-signed` without signature; `linux-namespace` without attach): exit non-zero naming condition *before* running (T33-S5, T29-S4, T08-S5). Windows `n/a` doctor lines (`doctor.go:50-51,124-126`) are named absence (exit 2), never pass (T33 gap 8).
- Networked verify/load (offline paths): verifier opens socket / follows redirect / consults registry-DNS → FAIL (air-gap means decision from bundle files alone; tested under disabled NIC) (T34 anti-toy 4).
- Each tool documents its own error mapping in its README (§T01–T34): HTTP status + how to parse `Detail` string; CLI exit codes (0/1/2 + per-verb 2–8 tables); library typed errors (`ErrUnmeasured`, `ErrBurstInvalid`, `UnavailableError` vs `BuildError`, `UnverifiedError` never silent). No bare-`0` error returns; every error names field/cause/remedy.

## 17. Supply-Chain Detailed Procedure (per release, no exceptions)

### 17.1 Build (producer, online; consumer offline)
1. **Pin toolchain.** `go 1.25` (`go.mod:3`), `bun` + frontend build (`Makefile:38-39`) **before** `go build` or `embed.go` ships stale `dist` (`README.md:304`). Frontend must be rebuilt *before* binary. Build command is the version of record (`cgo-dist.toml` `[inputs]` + `make`); ad-hoc shell history is not a build.
2. **Build binaries + archives** via `.goreleaser.yaml` (`builds` linux/amd64, windows/amd64, `-ldflags "-X main.version={{.Version}}"` so `cgo version` equals tag — R4: name the version, don't confuse `vX.Y.Z` tag with `X.Y.Z` version). `archives` → `cgo-<os>-<arch>.tar.gz`/`.zip`. `checksum` → `{{.ProjectName}}_{{.Version}}_checksums.txt` sha256 (R3). `sboms:` → per-archive CycloneDX (R2 §3; images excluded by R2 limitation — OCI SBOM goes in 17.3).
3. **Build OCI image(s).** Multi-arch index from multi-stage `FROM golang AS build` → `CGO_ENABLED=0 go build` → `FROM scratch` → `COPY --from=build /cgo /cgo` → `USER 65534` → `EXPOSE 9090` → `ENTRYPOINT ["/cgo","--serve"]` + `HEALTHCHECK CMD ["/cgo","healthcheck"]` (R9 instruction table). Set `org.opencontainers.image.title/version/revision/source/created` labels at build time (revision = git SHA; label namespace `unverified` beyond repo layout — use `opencontainers/image-spec annotations.md` as the reference when fetched, §4.4/§3.2). No `ARG GOOS/GOARCH` variance in assets.
4. **Freeze manifests + provenance (corpus side).** Per-run `manifest.json` + `config_sha256` (`book/tools/audit-archive.py:167-216`); corpus seal `docs/frozen-manifests.sha256` (159 lines, two-space/LF/sorted). `provenance.json` per asset (digest, commit, builder, toml hash, toolchain pin). Per bundle `provenance.json` (L1 digests+inputs+builder+toml hash). `MANIFEST.json` (bundle index: version, files[], modes, roles). Corpus attestation `emit` → `<artifact>.intoto.jsonl` (R4) (`subject`=corpus digest, `predicateType slsa/v1`, per-run `resolvedDependencies`, `builder.id=cgo-seal/<version>`).
5. **SBOMs (off-image for OCI).** Archives/binaries: GoReleaser `sboms:` (R2 §3). OCI image: `syft ghcr.io/.../cgo@sha256:... --output cyclonedx-json` → referrer/attestation or bundle file. Tool modules: own CycloneDX (R5 §3). Corpus: NOT an SBOM (seal+manifests+bundle is the equivalent).
6. **Sign.** Cosign sign image + archives + checksums (R6) with trust root shipped inside bundle for offline verification. SLSA provenance attestation as OCI referrer (L2). `signs:` for archives/checksums. Key custody decision in `cgo-dist.toml` (keyless OIDC vs self-managed — `unverified` until human decides §2.5).
7. **Version single-source.** Generate `internal/kit/KitVersion`, `VERSION`, frontend `package.json:version` from git tag in CI rather than three manual bumps (drift already warned in code). `cgo version` == tag == `VERSION` == `MANIFEST.json` version. `grep -rn "1.2.3" docs/` empty.

### 17.2 Publish (online; every asset digest-pinned)
1. Publish archives + `checksums.txt` + SBOM JSONs + provenance as GitHub release assets (GoReleaser `checksum` + `signs` output). GitHub release publish with SBOM + checksum files as first-class assets.
2. Publish OCI image **by digest** to `ghcr.io/realms4239/cgo` (R7 case (a)). Tag may also be pushed (`:<semver>`), but compose pins digest.
3. Push provenance as OCI referrer/attestation (L2). Release notes state achieved SLSA level per artifact (L1 with release; L2 once hosted signing; L3 non-goal).
4. Record prior digest before upgrade (`digest.txt` + `MANIFEST.json` prior digest field). Cutover hook §9.2 sequence (publish → bump `require` → `tidy` → `list` → dry-run → `keep_version` lock → `verify-fast` + selftest → verifier re-runs).

### 17.3 Offline load (offline host, zero network — verifies from bundle's own files)
1. Bundle = `docker save` OCI tarball (image @ digest) + digest-pinned compose + `cgo.conf` + `rules.yml` + `bin/cgo` archive + release SBOM + `SHA256SUMS`. Loader: `docker load`, `docker compose up`, `nginx -t && systemctl reload nginx`, `promtool check rules rules.yml` if promtool present.
2. If registry unavailable at edge, SBOM and provenance must be in bundle as files, not behind URL (R7 machine-readable SBOM useless if unreadable offline).
3. **Verify-before-run:** each file's sha256 against `SHA256SUMS` in bundle plus signed checksums from release (GoReleaser `checksum` + `signs`). Checksum verification is loader script step (`VERIFY.sh`/`verify.ps1` — `sha256sum -c`, provenance check, `docker load`), not manual. **Any code path that opens a socket during `verify` is a bug**, testable by running loader under disabled NIC in CI.
4. `VERIFIED` discipline: bundle that cannot verify in CI does not ship. Negative jobs (mutated binary, mutated SBOM, missing file, wrong digest — each must fail named error + zero execution). npm offline path: `npm install` on bundle-only host either installs from bundle or fails with "offline: use the bundle" — never silently hits `github.com` (replaces `npm/install.js:123-147` HTTPS path).

### 17.4 Rollback (tired-operator, one command, offline)
1. `docker inspect` running digest → write to `digest.txt` → edit compose → `docker compose pull && docker compose up -d` → `GET /api/health` → `cgo shape --restore` (host-side, since container `NET_ADMIN` is netns-scoped — container reach `unverified`, README states which: in-container `tc` vs host-side restore).
2. Release without named prior digest + one-command rollback (image digest + `cgo shape --restore`) that a tired operator can execute offline is a trap — `docs/deploy.md:182-183` rollback sentence must become literally executable against bundle `MANIFEST.json`.
3. Rollback drill (S6 in T34): record digest, upgrade, roll back by digest, verify `/api/health` + `cgo shape --restore`. Pasted digests before/after + health JSON into `docs/CHECKPOINTS.md` — VERIFY row moves only on this evidence (AGENTS.md roles).

### 17.5 Reproducibility gate
Two runs over identical inputs must produce **byte-identical** outputs for `emit`/`figures-check` (caller-supplied timestamp; no local path leak in bundle except caller-supplied). DWARF embeds source paths, so other build dirs change `bpf_probe.o` hash (`BUILD.md:45-48`) — same workdir required for predicate match (§8.6.1(d)). Same toolchain + same BTF + same workdir must reproduce pinned SHA, else investigate (spec §3.5).

## 18. Ledger / Citation Interface (the persistence contract)

### 18.1 What the ledgers are
Markdown ledgers + `tools/verify.py` are the entire persistence contract. No database, no SQLite/WAL, no object store for claims: `specs/2026-10-25:378` explicitly records "SQLite/WAL journaling — CSV append + manifest remains" as out of scope. (2) **Session persistence** (`CHECKPOINTS.md:1-4` "Append-only, newest at bottom…"; resume protocol `:6-13`; entry format `:15-28` Branch/HEAD, Changed, Proven (`<command → result, host>`), Unproven/blocked, Next; founding spec `engineering-system-design.md:390-414`). `ERRORS.md:1-18` third ledger ("an error without a cause is a rumor; a fix without a proof is a wish"; E1–E12 `:20-233`). (3) **Machine enforcement** (`verify.py:1-2` "Six-gate verifier. ### 18.3 Primary-source requirements (ledger)
SLSA Provenance v1.1 (R1/R2 ledger): `docs/VERIFY.md` rows **already carry R1-shape fields informally**: Claim ≈ `subject`, Evidence (command/path) ≈ `buildDefinition.externalParameters`, Date/Host ≈ `runDetails.metadata.startedOn` + `builder.id` proxy, verifier signature block (`:93-115`) ≈ `runDetails.builder.id` + per-gate `runDetails.metadata`. `frozen` gate's seal (`docs/frozen-manifests.sha256`, `verify.py:47-62`) is `resolvedDependencies` analogue — 159 `<sha256> <path>` lines, exactly ResourceDescriptor `(uri, digest)` pair (R1, ResourceDescriptor), and `architecture.md:76-83` says `ProvenanceSHA`/`ProvenanceHash8` are "injected in SVG, exported report and `/api/integrity`" — a `subject`-digest carrier (R1, Purpose). **What CGO lacks against R1/R2:** **(a)** no `predicateType` — no `"https://slsa.dev/provenance/v1"`-equivalent URI declaring which predicate VERIFY row satisfies (R1, `predicateType` MUST use URI, parse rules: consumers MUST ignore unrecognized fields, predicateType includes major version); **(b)** no authenticity — rows are unsigned Markdown, so R2-L2 "Provenance is Authentic" (signature validation, tamper evidence after build) not met; slice-11 checkpoint says this plainly: "this is a seal, not a signature; writer who can rewrite anchor too is out of scope" (`CHECKPOINTS.md:533-534`); **(c)** `builder.id` is hostname string (`DESKTOP-B6K9UCM`, `VERIFY.md:24`), not URI that "SHOULD resolve to documentation explaining scope, claimed level, accuracy guarantees" (R1, Builder `id`), same host string reused for builder and verifier passes, so "Consumers MUST accept only specific signer-builder pairs" (R1, Builder) cannot be enforced.
A standalone ledger tool therefore MUST, per R1 parsing rules, tolerate unrecognized fields (forward-compat), MUST version its predicate by major version in its type URI, and MUST NOT claim L2/L3 (authentic/unforgeable, R2) until it has signature + control-plane generation. Until then, claiming "SLSA L1" is itself overclaiming unless row carries subject-digest + how-produced fields at R1-`buildDefinition` completeness ("best effort" at L1 — R2, Provenance Exists, Completeness note).
CycloneDX SBOM (R3): frozen corpus (159 runs / 528 lines / 22 cells — `VERIFY.md:24`) **is** inventory in all but format: `docs/frozen-manifests.sha256` gives `(path, sha256)` per manifest (R3, hashes); per-run `manifest.json` files give component-like records; `pkg/figures` `ProvenanceSHA/Hash8` (`architecture.md:78-83`) is digest carrier. Standalone persistence module emitting CycloneDX BOM over `{Go module, bench scripts, book corpus, .dist artefacts}` would satisfy R3's `bomFormat`/`specVersion`/`components[].hashes|licenses|supplier|scope` fields — today CGO has data but emits none of envelope fields (no `serialNumber` UUID, no `metadata.timestamp`, no `specVersion`). `tools/verify.py` hygiene (forbidden paths, token/private-key scanning — `:344-388`) is SBOM-adjacent *license/exposure* check (R3, Expected Outcomes: "rapid identification of outdated components, licensing conflicts, or vulnerabilities"). But denylist, not inventory: proves absence of known-bad shapes (`ghp_…`, `AKIA…`, `xox[baprs]-` — `:308`), never enumerates components. R3 requires positive form: `components[]` list with names + versions + hashes + licenses (R3, components). Plan index `plans/README.md:27-58` is *work* inventory (slices with spec/plan/status/depends-on), not *component* inventory; conflating two is second-source-of-truth founding spec forbids ("A second copy is defect waiting to drift", `engineering-system-design.md:199-200`).
Semantic Versioning (R4): R4 §1 "Software using Semantic Versioning MUST declare public API. This API could be declared in code itself or exist strictly in documentation. However it is done, it SHOULD be precise and comprehensive." §§6–8: PATCH for backward-compatible bug fixes, MINOR for backward-compatible functionality (+ deprecations), MAJOR for backward-incompatible API changes, minor/patch reset on bumps (R4, §§6–8). §3: "Once versioned package has been released, contents of that version MUST NOT be modified" (R4, §3). §4: 0.y.z MAY change and not stable (R4, §4). FAQ: "v1.2.3 is not a semantic version" — `v`-prefixed strings are tag names, SemVer is `1.2.3` (R4, FAQ). CGO mapping: VERIFY row schema, CHECKPOINT entry schema, six-gate CLI (`--fast/--staged/--only/--list/--selftest` — `verify.py:479-484`) **are** public API in R4's sense: writers (builder sessions) and readers (verifier sessions) interoperate through them, and breaking change (renaming status, changing verdict contract) would silently corrupt in-flight claims. Yet neither schemas nor gate layer declares version: `tools/verify.py` has `MAX_GATE_LINES = 650` (`:11`) but no `__version__` / `ledger_version`; `docs/VERIFY.md` grew `SUPERSEDED` from founding five statuses (`engineering-system-design.md:349-358` → `VERIFY.md:7-18`) without version bump or migration note recorded anywhere in `CHECKPOINTS.md` or `ERRORS.md` (grep: **unverified — primary source not found** for any "ledger v2" note). Per R4 §1/§4, standalone tool must declare API preciously: start at `0.y.z` (MAY change), move to `1.0.0` only when row schemas + CLI + verdict contract are pinned as compatibility promises, treat released `vX.Y.Z` tags as immutable (R4 §3).
gitignore (R5): DESCRIPTION: "A `gitignore` file specifies intentionally untracked files that Git should ignore. **Files already tracked by Git are not affected**" (R5, DESCRIPTION), NOTES: "The purpose of gitignore files is to ensure that certain files not tracked by Git remain untracked. To stop tracking a file that is currently tracked, use `git rm --cached`" (R5, NOTES). Patterns read from (high→low): command line, `.gitignore` files same/parent directories, `$GIT_COMMON_DIR/info/exclude`, `core.excludesFile` (R5, DESCRIPTION). Only version-controlled, shared patterns belong in committed `.gitignore` (R5, DESCRIPTION, "Which file to place a pattern in"). CGO mapping: `.gitignore:69` (`/book/`) plus `data/runs/`, `data/logs/` (`.gitignore:21-22`) and `*.docx / *.pdf` (`.gitignore:66-68`) mean **measurement corpus, thesis book, and all live-run output intentionally untracked** — correctly, per R5's purpose. Persistence layer therefore cannot be "git history": git literally does not carry frozen corpus, and fresh clone has no `book/` so `frozen`/`provenance` SKIP (exit 2 — `verify.py:65-66`, `CHECKPOINTS.md:176-178`). R5's "Files already tracked are not affected" cuts other way for 18 legacy `backup/*.tar.gz` archives: they were tracked *before* `backup/` rule, so ignoring `backup/` does not untrack them — why hygiene gate needs exact-path `LEGACY_ARCHIVES` allowlist (`verify.py:316-323`) rather than pattern fix. To stop tracking them you would need `git rm --cached` (R5, NOTES) — human decision still open (`CHECKPOINTS.md:153-155`). `.gitignore` in this repo also carries product decisions disguised as ignore rules: `DIST` (`web/frontend/dist/*` with `!web/frontend/dist/index.html` — `.gitignore:11,35`), `vmlinux.h` (`.gitignore:17`), `kit/chr/cache/` (`.gitignore:82`). Standalone tool must distinguish *persistence policy* ("never commit `book/`", `AGENTS.md` Never-commit list — `engineering-system-design.md:227-229`) from *build-artifact exclusion* (no need to version `vmlinux.h`). R5 helps: only patterns that "all developers will want to ignore" belong in committed file (R5, DESCRIPTION); everything else is `info/exclude` / `core.excludesFile` territory.
**What primaries do NOT require (avoid citation theatre):** Neither R1 nor R2 requires Markdown ledger, `VERIFIED` status, or checkpoint format — those are CGO-local invention (`engineering-system-design.md:32-36`). SLSA requires subject+how-produced fields *however they are carried*; Markdown can carry them, but carry does not inherit SLSA's authenticity (R2-L2) without signatures (see §4.1). R3 does not require inventory to be gitignored or tracked — `scope: excluded` (R3, scope) is mechanism for "present but not required"; CGO uses gitignore instead, different mechanism (R5 tracking vs R3 scope) and standalone tool must not conflate them. R4 does not require semver on *documents*; requires it on *code/tool's public API*. Versioning `docs/VERIFY.md` itself is design choice module may make (ledger format version), not R4 mandate — but once tool declares ledger format, R4 §1 requires that declaration to be precise. "Ledger conventions" named in brief (append-only + no-delete + checkpoint-at-handoff) are **CGO-local** — founding spec attributes them to AIR/DIS synthesis (`engineering-system-design.md:19-36`), and AIR/DIS primaries were not fetched in this pass (**unverified — primary source not found**). ### 18.4 Gaps (ledger)
1. **Docs are only persistence layer because git deliberately does not carry evidence.** `.gitignore:69` ignores `/book/`; `.gitignore:21-22` ignores `data/runs/` and `data/logs/`. R5 says gitignore makes files "remain untracked" (R5, NOTES) — so `git log` cannot reconstruct 159-run corpus, thesis, or any live run. `VERIFY.md:1-5` rule ("The row is source of truth; prose is not") exists *because* there is no other store: `enterprise-rebuild-design.md:378` records "SQLite/WAL journaling — CSV append + manifest remains" as refused. If ledgers deleted, *interpretation* of CSVs lost even though CSVs survived — why `VERIFY.md:83-91` forbids deleting `REFUTED`/`SUPERSEDED` rows: they are history, and history has no other home.
2. **Corpus seal self-referential without ledger.** `frozen` gate checks manifests against per-run SHA-256s (`verify.py:60-62`) **and** against committed anchor `docs/frozen-manifests.sha256` (`:47-62`). Against R2, this is L1-at-best ("best effort" completeness, R2/Provenance Exists): catches *stale* manifest, not *forged* one. Ledger is only thing that names limit — seal format does not.

### 18.5 Target decomposition — three tools, not one
Requirement names three tools. Decomposition justified by three different readers and three different write patterns:
* **Writer of claims** (builder session) — appends rows; never rewrites history.
* **Reader that runs gates** (verifier session / hook) — executes; never edits.
* **Reader that quotes number out of repo** (thesis / report / UI) — cites; never writes.
Collapsing into one binary loses SLSA separation R1 requires between `buildDefinition` (inputs), `runDetails.builder.id` (who ran), consumer's verification (R1, Model; R2, split of duties between producer and build platform). Three small tools with thin shared schema minimal complete decomposition; one tool with three subcommands same thing with marketing name. Schemas are API (R4 §1) — declare them first.
#### 18.5.1 Ledger tool (`ledger`) — owns three Markdown ledgers as data
* **Owns:** parsing, validating, appending `VERIFY.md`, `CHECKPOINTS.md`, `ERRORS.md`, plus plan-index slice map (`plans/README.md:27-58`) as read-only view. Only writer.
* **Contract (illustrative; shape is deliverable, per R4 §1):**
```text
ledger add-row --claim "..." --status VERIFIED|RECORDED|PENDING|BLOCKED|REFUTED|SUPERSEDED --evidence "<command or path>" --date YYYY-MM-DD --host ...
ledger move-row <id> --to VERIFIED|BLOCKED ...  # BLOCKED→PENDING requires named condition text; VERIFIED requires non-empty evidence
ledger checkpoint --focus "..." --branch ... --head ... --changed ... --proven ... --unproven ... --next ...
ledger error --title ... --symptom ... --cause ... --fix ... --proof ... --lesson ...
ledger validate          # schema + status-closed-set + "every BLOCKED names a condition" + "every VERIFIED names command+host+date"
ledger signature ...     # writes verifier-signature block shape (VERIFY.md:93-115)
```
* **Why tool not template:** today rule "only named command on named host moves row" (`VERIFY.md:83-91`) is prose enforced by verifier's memory. Ledger tool makes move *structurally* impossible otherwise (edit changing status without evidence fails validation) — difference between persistence contract and style guide. R1's `externalParameters` MUST-be-verified-downstream (R1, BuildDefinition) maps to `Evidence` being required field, not convention.
#### 18.5.2 Gate tool (`gate` / `verify`) — owns `tools/verify.py` + hooks, and nothing else
* **Owns:** six gates + fault proofs + ceiling + verdict + hook selection (`verify.py:454-523`, `:478-523`). Real (non-fixture) verification belongs here.
* **Contract:** keep current CLI shape (`verify [--fast|--staged|--only NAME]`, `--list`, `--selftest` — `:479-484`, `Makefile:24-36`) because hooks and checkpoints already depend on it (`CHECKPOINTS.md:159-203`). Add `--json` emitting CycloneDX-shaped inventory for gate-relevant inputs (R3: `components[]` with `hashes`, `supplier`, `scope`) so "which Go module version did `tests` run" attestable next to verdict — closing gap §5.5 without new gate.
* **What it does NOT own:** ledgers. Today `hygiene` + `links` read ledgers as *paths to scan* (`:392-393`) — that stays. But gate never edits them; slice-11 precedent correct: gate *enforces* ("gate only reads anchor" — `CHECKPOINTS.md:568-571`), ledger *records*. Merging two re-introduces self-authored-verification failure spec's Law 6 exists to prevent (`engineering-system-design.md:190-193`).
#### 18.5.3 Citation tool (`cite`) — owns "how number leaves repo"
* **Owns:** turning `VERIFIED` ledger row + artefact digest into portable citation record downstream reader can re-verify without repo.
* **Contract (illustrative):**
```text
cite <row-id>            # emits s<a>L<S>A>-shaped JSON (R1 predicate type) with:
                         #   subject: {name, digest: sha256}   (artefact, R1 subject)
```

* **Why tool not doc paragraph:** R1 requirement is consumers "can verify artifact was built according to expectations" and "can rebuild artifact, if desired" (R1, Purpose). Copy-pasted paragraph in thesis cannot be verified; JSON record with `subject.digest` + `resolvedDependencies` can (R1, ResourceDescriptor). Frontend "CITER CE RAPPORT" action (`CHECKPOINTS.md:712-721`) already builds this shape from report fields — tool generalises it from one report to *any* VERIFY row, UI then copies tool's output instead of hand-assembling strings.
* **Honesty note (R2):** until citation record signed by builder identity (R2-L2 Authentic, R2-L2 Authentic), `cite --verify` validates *shape + digest consistency*, not authenticity — record must say so in `authenticity: unsigned-local-seal` field rather than implying L2. Slice-11 precedent ("seal, not signature" — `CHECKPOINTS.md:533-534`) is model.
