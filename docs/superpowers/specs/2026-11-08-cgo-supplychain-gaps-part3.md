## Appendix K — Versioning Discipline + Stop-and-Ask (copy into every module README)

1. **Declare public API** (SemVer §1): README lists every exported symbol + JSON wire schema + CLI verbs + exit-code contract. Pre-`1.0.0` MAY break freely but must say so; the README is the compatibility promise once tagged `vX.Y.Z`.
2. **Tags** are `vX.Y.Z` (Go canonical). The version string is `X.Y.Z`. Tag = version? No — tag includes `v`; version does not. Never move a tag. Never edit contents post-release (SemVer §3).
3. **Increments:** PATCH = backward-compatible bug fix; MINOR = backward-compatible functionality (+ deprecations); MAJOR = backward-incompatible (removal/rename/type break) + **`/vN` path suffix** (Go Modules import-compatibility rule). Deprecation needs ≥1 minor cycle before removal (SemVer FAQ).
4. **Single source:** `KitVersion` / `VERSION` / `package.json` / `cgo version` / bundle `MANIFEST.json` / SBOM `version` generated from **one** git tag in CI (never three manual bumps). `-X main.version` == tag (or CLI and GUI diverge — `main.go:36-40`).
5. **Version bumps follow cutover (§9.4):** tag → `require` → `tidy` → `list` → dry-run → `keep_version` lock → `verify-fast` + selftest → verifier re-runs.
6. **Stop-and-ask** (every module, no exception): new dependency; destructive action; live bench run; merge to `main`; secret exposure; frozen-data change; scope growth (≥3 active slices). Ask before acting, not after.
7. **Version discipline checklist (blocker for tag):** declared API in README (godoc + `docs/CLI.md`/`docs/cgo-*-api.md` where applicable); `go.mod` path + `go 1.25` floor; `go.mod`/`go.sum` committed; `CHANGELOG.md` MAJOR/MINOR/PATCH phrasing; `LICENSE` (MIT); frozen schemas byte-identical (`pkg/model/types.go:171-184`); no `replace` in release tag; `make verify` green.
8. **Pathspec / commit hygiene:** stage explicit paths (never `git add -A`); one logical group per commit; never commit `epbfBBR.md`/`critical-review-*`/`session-*`/`handoff-*`/`backup/`/`data/`/`book/`/`*.docx/*.pdf`/`cgo.exe`/archives; check checkpoint entry format (Branch/HEAD/Changed/Proven/Unproven/Next) and cite it in the checkpoint (`docs/CHECKPOINTS.md:15-28`).
